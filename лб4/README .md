## Таблица трассировки цикла суммирования чисел 1–4

Пример кода:
```python
total = 0
for i in range(1, 5):
    total = total + i
```
    
| Итерация | Значение `i` до тела | `total` до | `total` после |
|----------|----------------------|------------|---------------|
| 1 | 1 | 0 | 1 |
| 2 | 2 | 1 | 3 |
| 3 | 3 | 3 | 6 |
| 4 | 4 | 6 | 10 |
| — | цикл завершён | 10 | (итог 10) |

**Проверка:** `1 + 2 + 3 + 4 = 10` да

---
### Почему цикл завершится

- В `positive_input.py` цикл `while` продолжается, пока условие истинно (`число <= 0`). При вводе положительного числа условие становится ложным, и цикл завершается.
- Гарантия завершения: по условию задачи пользователь **обязан** рано или поздно ввести положительное число; тип `int` гарантирован, поэтому бесконечного ожидания корректного ввода не будет.
- В `statistics.py` и `variant.py` используется цикл `for` с известным числом итераций `range(n)`, где `n >= 1` (или `n >= 0` в варианте) — цикл завершится ровно за `n` шагов.

### Почему `range(a, b)` не всегда соответствует заданию №1

- `range(a, b)` в Python **не включает** правую границу `b`. Например, `range(1, 5)` даёт `1, 2, 3, 4` — без `5`.
- В задании №1 требуется вывести числа **от `a` до `b` включительно**.
- Поэтому для возрастания нужно `range(a, b + 1)`, а не `range(a, b)`.
- При убывании `range(a, b - 1, -1)`: шаг `-1`, и правая граница должна быть на единицу меньше, чтобы включить `b`.
- При `a == b` обычный `range(a, b)` дал бы **пустой** диапазон, а по заданию нужно вывести одно число — значит, нужна отдельная ветвь.
- Вывод: `range(a, b)` корректен только для полуинтервала `[a, b)`, а задание требует замкнутый отрезок `[a, b]`.
